# Retro: why the redesign went in circles (June–July 2026)

Written 2026-07-14 after a full audit of the branch, docs, and git history.
Keep this short and honest — it exists so the pattern gets recognized early
next time.

## The observable loop

- The plan grew from R1–R5 to R1–R8, with R8 splitting into
  R8A/R8B/R8B.2/R8C.1–4/R8D plus an abandoned "marathon" worktree and a
  salvage matrix. R2's exit gate ("re-measure the benchmark") never closed;
  it was still formally open when R8 started.
- The archived R8 log records **eleven consecutive "stop checkpoints"**,
  each with two rejected hypotheses, over ~5 days. 49 commits landed on
  2026-07-14 alone. Agents repeatedly reported "fixed"; the screen kept
  disagreeing.
- The rewrite motivated by a 6,100-line `FrameRenderMixin` produced a
  ~10,800-line successor spread over six modules bound into one object,
  plus a 106-field `FrameSession`.

## The five mechanisms

1. **Counters became acceptance.** Exit gates were machine-checkable
   internals (upload counts, lifecycle agreement, settlement predicates).
   The R8 log itself says it: "Those counters are not acceptance evidence.
   Visual observation found…" — yet the next gate was another counter.
   Nothing cheap and repeatable asserted *pixels on a real display*, so
   every "fixed" claim was a unit-test claim.

2. **Fixes narrowed predicates instead of unifying owners.** Coverage ring
   → onscreen → strict intersection → physical targets: each fix shrank a
   set to make one symptom pass, and each shrink stranded tiles some other
   subsystem still believed in (→ black tiles). The codebase holds the same
   fact ("which level is resident", "which tiles are visible", "tile
   priority") in 3–8 places; every fix that synchronized two of them
   desynchronized a third.

3. **Tests pinned the bug.** Regression tests were written for the narrowed
   predicates themselves (`…scoped_to_onscreen_targets`,
   `…excludes_tiles_that_only_touch_the_viewport_boundary`), so the next
   agent treated the regression as a contract. The suite passing became
   evidence of the wrong thing.

4. **Process rewarded stopping, not finishing.** The two-hypothesis stop
   rule + checkpoint commits + ever-growing constitution docs meant each
   session ended by writing more rules for the next session, which spent
   its first hours re-deriving context from them. Meanwhile the actual
   user-visible complaints (priority order, black tiles) were declared
   *out of scope* of the active gate ("scheduling remains out of scope",
   "R8D blocked").

5. **Silent fallbacks hid deletions.** "Delete aggressively" was right, but
   `except Exception` import shims let deleted modules keep "working" —
   `montage_prefetch.py` has imported a nonexistent module since R7 with
   zero test failures.

## The counter-rules (now in the README)

Pixels are the gate; fix by deleting a duplicate; implementation-detail
tests are deletable; no silent fallbacks; bounded sessions that end visibly
better or reverted. And one meta-rule: **when a plan document needs a
sub-lettered sub-phase (R8C.3), stop and re-scope — the plan is describing
the maze, not the exit.**
